## 사용자의 실제 계획

사용자가 선택한 할 일은 운동, 네트워크 관리사 2급 공부, 네트워크 강의 복습, ALEPH 과제, 듀오링고(영어·일본어)입니다. 첫 접속 시 계획 하나와 할 일 다섯 개를 원자적으로 저장합니다. 2026-10-13~20, 총 360분은 수정 가능한 계획 초안입니다. 각 예상 시간은 60·90·90·90·30분입니다. 실제 실행 기록은 자동으로 만들지 않습니다.

## 기능

- 일반 할 일·시험/일정·기간 할 일 선택, 시험 날짜/선택 시각, 기간 시작일/종료일 저장
- 시험 D-day와 기간 전체 예상 시간 표시, 진행 기간에 걸쳐 달력 표시하되 한 작업·완료 1회로 관리
- 일간 날짜 선택, 월~일 주간 보기, 월간 달력, 이전·다음·현재 기간 이동 및 전체/기간 지정 보기
- 선택 기간에 진행하는 일정 목록과 마감일 기준 집계, 서울 시작일 기준 실행 목록, 달력 날짜 클릭으로 일간 이동
- 계획의 기간·우선순위·성공 기준·예상 시간과 모든 버전의 수정 이력
- 할 일 추가·수정·완료·완료 취소·삭제, 검색·상태/우선순위/태그 필터·안정적인 정렬
- 할 일 아래 세부 체크리스트: 추가·수정·삭제·완료·완료 취소, 전체 메모 보존 및 메모에서 항목 나누기
- 새로 만드는 반복 일정에는 세부 체크리스트를 복사하고 완료 상태는 초기화
- 시간·분 분리 입력과 시간 단위 표시; 저장·내보내기 단위는 분으로 유지
- 기존 할 일의 ‘반복’에서 최대 31일과 요일을 선택해 날짜별 할 일 일괄 생성. 날짜별 완료·실행 기록은 독립적이며 같은 날짜 요청 재시도 중복 방지
- 날짜별 목록, 제목 뒤 날짜 수기 입력 없이 마감일에서 날짜 관리
- 시작·종료 시각, 실제 분, 막힌 이유, 메모를 할 일에 연결해서 별도 저장
- DB UNIQUE 제약과 atomic batch를 사용하는 중복 완료 방지 및 실행 기록 재시도 방지
- 마감일 기간별 집계와 숫자별 근거 기록; 삭제한 할 일 제외, 서울 기준 지연 계산
- 돌아보기 스냅샷과 개선점 한 줄을 이어받은 다음 계획
- 수정 이력과 삭제한 할 일까지 포함한 JSON 파일 하나로 내보내기

## 기술 및 데이터

React, TypeScript, Vinext, Cloudflare Worker와 실제 D1 데이터베이스를 사용합니다. .openai/hosting.json의 DB 바인딩은 배포 플랫폼이 연결합니다. 브라우저 localStorage는 기록 저장에 사용하지 않습니다. 서버에는 비밀 API 키가 필요하지 않습니다.

최종 표·항목·관계·날짜·집계 규칙은 `contracts/pds-schema-v2.json`에 있습니다. 마이그레이션은 `drizzle/`에 있으며, 이미 배포한 마이그레이션은 수정하지 않습니다.

## 공개 사용

링크를 아는 방문자는 기록을 읽고 수정·삭제할 수 있습니다. 공개해도 되는 계획과 기록만 넣습니다. 첫 화면에 과제 원문의 공개 안내를 표시합니다. 사용자 문자열은 React의 텍스트로 출력하고 SQL은 바인딩으로 전달합니다. 실행 시각은 UTC로 저장하고 서울 시간으로 보여 줍니다.

월간·주간 달력에서 시험·일정을 먼저, 기간 할 일을 다음으로 표시합니다. 하루에 최대 3개 이름과 나머지 개수를 보여 주며, 날짜를 누르면 해당 일간 목록으로 이동합니다. 보라색 시험 카드와 파란색 기간 카드, 아이콘·이름·날짜가 함께 표시됩니다. 선택 기간의 주요 일정 카드에서 전체 이름과 날짜, D-day를 확인하고 수정할 수 있습니다. 이 변경은 저장 데이터와 집계 규칙을 바꾸지 않습니다.

## 카드 3 완료 확인

목록의 ‘완료’ 전용 버튼은 완료 요청만 보내며 재클릭으로 취소하지 않습니다. 왼쪽 큰 체크박스로는 기존처럼 완료를 취소할 수 있습니다. 완료된 할 일과 연결된 실행 기록 아래에 현재 완료 회차에 저장된 완료 이벤트 수와 ID·서울 시각을 표시합니다. 실행 기록과 완료 이벤트는 별도 표이며, 완료 버튼은 실제 실행 시간을 만들지 않습니다. DB의 task_id+cycle 및 request_key 고유 제약과 atomic batch가 중복을 차단합니다.

## 기록의 메모와 막힌 이유 보완

실행 목록의 ‘메모·막힌 이유 수정’으로 기존 기록의 blocked_reason과 note를 수정합니다. 시작·종료 시각, 실제 분, 기록 ID, 연결된 할 일 ID와 원래 계획을 보존하며 실행 기록을 추가 생성하지 않습니다. 삭제한 할 일에 연결된 기록은 이 경로에서 수정하지 않습니다.

### 계획 삭제

계획 상단의 ‘삭제’를 누르면 계획 이름·기간·연결된 할 일과 실행 기록 수를 확인한 뒤 삭제할 수 있습니다. plans.deleted_at만 저장하고 선택 목록과 집계에서 제외합니다. 모든 이력·할 일·실행 기록·돌아보기와 다음 계획 연결은 전체 내보내기에 보존합니다. 삭제된 계획의 오래된 화면에서 보내는 변경은 서버가 거절합니다. 삭제된 다음 계획은 원래 돌아보기에서 ‘연결된 계획 삭제됨’으로 표시하며 같은 돌아보기로 중복 생성하지 않습니다. 마지막 계획을 삭제해도 새 계획 작성이 가능합니다.

## 전체 자료 내보내기

‘전체 자료 내보내기’는 같은 화면에서 서버의 전체 JSON을 불러와 표별 기록 수와 원문을 보여 줍니다. ‘파일 저장’은 지원되는 브라우저에서 저장 위치를 선택하고, 그 외에는 JSON Blob 다운로드를 요청합니다. 파일이 차단되면 ‘JSON 복사’ 또는 원문 전체 선택으로 복사해 pds-diary.json 파일 하나로 저장할 수 있습니다. 서버 오류·HTML·누락된 표·잘못된 날짜/단위는 저장하지 않습니다. 내보내기는 운영 자료를 수정하지 않습니다.
